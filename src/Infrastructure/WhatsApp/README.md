# Контракт транспорта

Адаптер проверен по исходникам WPPConnect Server Go
[`cf1098f91c1a1e2028e5d864490f45c72f6b8358`](https://github.com/wppconnect-team/wppconnect-server-go/tree/cf1098f91c1a1e2028e5d864490f45c72f6b8358)
и закреплённому SDK whatsmeow
[`9d2171c39a1037e867d7df1b9188757d27634918`](https://github.com/wppconnect-team/whatsmeow/tree/9d2171c39a1037e867d7df1b9188757d27634918).
Локальный Dockerfile применяет совместимость API и исправление WebSocket-кадров;
версию сервера, SDK и оба патча следует рассматривать вместе.

## HTTP и текст

- Bearer token передаётся только заголовком. HTTP разрешён на loopback; HTTPS проверяет сертификат.
  Переходы по redirect, HTTP-повторы и прокси из окружения отключены.
- Пустой список разрешённых получателей запрещает отправки. Отправка принимает только
  подтверждённый PN в виде цифр, одного получателя и `isGroup:false`.
- Локальный приёмник получает тот же список разрешённых PN: входящие сообщения от
  остальных аккаунтов и от неизвестного LID не создают анкет или ответных заданий.
  Пропуск сохраняет идентификатор события и курсор; исходный текст не записывается.
- Сервер ограничивает JSON 128 KiB, текст — 65 536 Unicode-символами, запрещает пустой
  текст и NUL. Разбиение сохраняет символы и ограничивает часть 60 000 UTF-8 байтами;
  дополнительная проверка учитывает расширение управляющих символов при JSON-кодировании.
- HTTP-ответ ограничен 3 MiB, заголовки — 16 KiB. Таймаут соединения 5 секунд,
  чтения 15 секунд, отправки 70 секунд при серверном контексте отправки 60 секунд.

Источник: `internal/httpapi/message_actions.go`, `internal/messages/actions.go`.

## Достоверность результата

HTTP 201 с ID и совпадающим получателем означает принятие транспортом. Оно не означает
доставку или прочтение. Потеря ответа, 408 и 5xx после POST, неожиданный ответ или redirect
означают `uncertain`; адаптер их не повторяет. Только доказанный отказ до отправки запроса
может означать безопасную недоступность. 429 возвращается до вызова SDK, поэтому допускает
отложенный повтор. Необработанный текст ошибок upstream не включается в исключения PHP.

Отдельной долговечной очереди исходящих HTTP-отправок в обработчике не обнаружено.
В SDK есть [повтор кадра с прежним ID](https://github.com/wppconnect-team/whatsmeow/blob/9d2171c39a1037e867d7df1b9188757d27634918/request.go#L185)
после восстановления соединения и
[обработка retry receipts с прежним ID](https://github.com/wppconnect-team/whatsmeow/blob/9d2171c39a1037e867d7df1b9188757d27634918/retry.go#L208).
Это не основание обещать доставку «ровно один раз». Новый PHP POST после неопределённого
результата мог бы создать новое сообщение с другим ID.

## События и PN/LID

`events` возвращает записи по возрастанию sequence, до 200 за запрос и приблизительно
2 MiB данных. PHP продвигает курсор только вместе с эффектами события; поля `nextCursor`
недостаточно для подтверждения обработки. Входящие сообщения дополнительно дедуплицируются
Kernel по message ID. Пропущенные события сохраняют только идентификаторы конверта;
QR, собственные сообщения, группы и вложения не запускают регистрацию.

LID остаётся непрозрачным идентификатором. PN берётся из адреса с сервером PN либо
из проверенной пары `phoneNumber/lid` authenticated endpoint `contact/pn-lid`.
Ошибка запроса mapping сохраняет входящий курсор перед событием; успешное отсутствие
mapping разрешает регистрацию с непрозрачным LID. Последующий mapping сохраняет тот же
внутренний аккаунт через aliases Store. Отправка на неизвестный LID запрещена.

Квитанции обрабатываются через `onack`: пустой тип — `delivered`, `read` — `read`.
`read-self`, неизвестные типы и группы не подтверждают доставку. Квитанция связывается
с сохранённым ID сообщения и подтверждённым PN. Неизвестный mapping сохраняется в отдельной
таблице вместе с продвижением курсора; до десяти отложенных записей за цикл повторно
сопоставляются, не блокируя новые события. Store сохраняет также квитанции, пришедшие
раньше записи успешного ответа отправки. Endpoint `message-receipts` не используется:
его история под PN может не совпасть с квитанцией под LID.

Источники: `internal/httpapi/events.go`, `internal/eventbus/store.go`,
`internal/httpapi/directory.go`, `internal/media/event.go`, `internal/notifications/protocol.go`.

## Ограничения эксплуатации

Журнал сервера по умолчанию доступен через GET только за последние семь дней, ограничен
100 000 событиями и 128 MiB. Длительный простой приёмника может потерять входящие события;
сохранение исходящей очереди PHP не устраняет это ограничение upstream.

SDK пишет диагностические сообщения с адресами. В изолированном compose транспорта
используется `logging.driver: none`; приватный каталог сессии и истории также содержит
чувствительные данные. Безопасные ошибки PHP не заменяют эту защиту транспорта.

Автоматические тесты используют фейки HTTP и временную SQLite. Они не доказывают доставку
живому аккаунту, пределы WhatsApp на реальном соединении или восстановление SDK после
сбоя сети; эти проверки выполняются отдельно на разрешённом локальном стенде.
