# Установка на Ubuntu без Docker

Установщик обновляет **существующий** Telegram-бот и добавляет MySQL, WhatsApp и HTTPS-вложения. Поддерживаются Ubuntu 22.04/24.04, PHP 8.4, systemd и архитектуры amd64/arm64. Код берётся из `deepl-translate`. Docker на сервере не нужен.

До запуска разработчик должен получить root/sudo, положить Excel с контактами на сервер и направить отдельный свободный поддомен на этот сервер. Для сертификата нужны доступные извне порты 80/443 и email администратора. Условия Let's Encrypt принимаются командой `install --email …`. Если DNS содержит AAAA, IPv6 тоже должен вести на этот сервер.

Ожидаются уже рабочие `.env`, SQLite и службы `telegram-broadcast-poll.service` / `telegram-broadcast-worker.service`, запускаемые от отдельного пользователя. PHP 8.4 и его APT-репозиторий должны быть настроены. Существующий MySQL использует локальную административную авторизацию root через socket; установщик не меняет пароль root. Нестандартную конфигурацию он не перезаписывает.

Для проверенного сервера каталог — `/var/www/telegram-broadcast`, пользователь служб — `gretail`. У SSH-пользователя `olegb` сейчас **нет** достаточных sudo-прав: эти команды выполняет разработчик/администратор. На самом сервере установщик в рамках разработки не запускался.

## Первый запуск — 7 команд после входа на сервер

Замените `admin@example.org` своим email, а `/root/contacts.xlsx` — путём к Excel. `service.imenka.world` должен быть отдельным свободным доменом для вложений; при необходимости замените его.

```bash
sudo systemctl stop telegram-broadcast-poll telegram-broadcast-worker
sudo -u gretail git -C /var/www/telegram-broadcast pull --ff-only origin deepl-translate
sudo python3 /var/www/telegram-broadcast/deploy/install.py install --domain service.imenka.world --email admin@example.org
sudo python3 /var/www/telegram-broadcast/deploy/install.py pair
sudo python3 /var/www/telegram-broadcast/deploy/install.py import /root/contacts.xlsx --apply
sudo python3 /var/www/telegram-broadcast/deploy/install.py start
sudo python3 /var/www/telegram-broadcast/deploy/install.py status
```

`install` устанавливает зависимости, сохраняет резервную копию, создаёт базу `broadcast_contacts` и пользователя MySQL со случайным паролем, собирает закреплённый Go-транспорт, применяет миграции, настраивает службы и HTTPS. Из старого `.env` сохраняются Telegram/DeepL/почтовые настройки и `DATABASE_PATH`. SQLite не заменяется тестовой базой. Пароли и токены не выводятся. Первая сборка занимает несколько минут, особенно на сервере с 2 ГБ памяти.

`pair` показывает QR в терминале. Сканируйте его **с телефона нового отправителя**: WhatsApp → Связанные устройства → Привязка устройства. Создаётся отдельная серверная сессия `whatsapp-production`; локальная тестовая сессия не переносится. Если аккаунт уже подключён, повторная команда его сохраняет. Подключение другого аккаунта вместо уже связанного требует отдельного обслуживания: команда не делает скрытый logout.

`import --apply` сначала проверяет весь файл, затем импортирует именно проверенную копию. Поддерживаются столбцы `phone`, `language`, необязательный `email`, а также русский и прежний формат таблицы. Для исходного списка с продолжениями в строках 5 и 9 добавьте **только если это тот же файл**: `--continuation-row 5 --continuation-row 9`. Ошибки печатаются как номер строки и код, без содержимого ячеек. Проверить без записи можно той же командой без `--apply`.

После импорта allowlist формируется из активных WhatsApp-контактов MySQL. Ранее отключённые контакты не включаются повторным импортом. После ручных изменений каталога выполните `stop`, затем `start`: список разрешённых номеров обновится.

`start` проверяет конфигурацию, MySQL, подключение WhatsApp и реальное скачивание контрольного файла через HTTPS. Только затем включает обработку очереди; 70 секунд наблюдает службы, включая повторные падения poll. При частичном запуске или падении останавливает процессы бота. Одобренные ранее задания очереди продолжат выполнение. Команда не создаёт тестовую рассылку: после запуска отправьте контролируемый тест из Telegram и проверьте доставку с нового WhatsApp-номера.

## Следующее обновление

```bash
sudo python3 /var/www/telegram-broadcast/deploy/install.py stop
sudo -u gretail git -C /var/www/telegram-broadcast pull --ff-only origin deepl-translate
sudo python3 /var/www/telegram-broadcast/deploy/install.py update
```

`update` применяет **уже скачанный код**: резервная копия → Composer → миграции → службы → проверки → запуск. Номер, сессия, ключ ссылок и пароль MySQL сохраняются. `stop` также отключает автозапуск процессов бота до `start`, чтобы перезагрузка во время обслуживания не возобновила рассылку. При прерывании установки повторите `install` с теми же параметрами; автоматического запуска не будет.

## Файлы и службы

| Назначение | Путь / имя |
|---|---|
| Состояние установщика и секрет транспорта | `/etc/telegram-broadcast/` (root) |
| Бинарные файлы транспорта и лицензии | `/opt/telegram-broadcast-transport/` |
| Новая WhatsApp-сессия | `/var/lib/telegram-broadcast/whatsapp/` |
| Вложения / ключ новых ссылок | `/var/lib/telegram-broadcast/attachments/`, `/var/lib/telegram-broadcast/private/` |
| Резервные копии | `/var/backups/telegram-broadcast/` (root) |
| Бот | `telegram-broadcast-poll`, `telegram-broadcast-worker`, `telegram-broadcast-whatsapp-poll` |
| WhatsApp-транспорт | `telegram-broadcast-whatsapp` (только `127.0.0.1:21465`) |
| Скачивание | `telegram-broadcast-downloads`, `telegram-broadcast-download-db` |

Если пути вложений и ключа уже заданы, они сохраняются. Менять домен существующих ссылок установщик не разрешает. Nginx получает только маршрут `/download/<token>`, без публичного доступа к каталогу файлов. PHP-FPM работает от отдельного пользователя, которому недоступны `.env`, токены и ключ подписи. Служба `download-db` держит SQLite-соединение без транзакции, чтобы WAL/SHM оставались доступными для чтения даже при остановленных poll/worker. Она не обрабатывает очередь.

Certbot обновляет сертификат таймером и перезагружает Nginx. При занятом домене установка завершается с понятной ошибкой, сохраняя существующий сайт. Пароли базы доступны боту через `.env`; служебные токены — в `secrets/`. Эти данные не коммитятся.

## Диагностика и резервирование

```bash
sudo journalctl -u telegram-broadcast-poll -u telegram-broadcast-worker -u telegram-broadcast-whatsapp-poll -n 100 --no-pager
sudo python3 /var/www/telegram-broadcast/deploy/install.py backup
```

`backup` оставляет бот остановленным; скачивание и транспорт тоже останавливаются для согласованного копирования. Сохраняются SQLite через online backup API с проверкой целостности, MySQL dump, вложения, ключи, OAuth, WhatsApp-сессия, настройки и тексты unit-файлов. `manifest.json` содержит исходные пути и SHA кода. Резервные копии содержат персональные данные и секреты; доступ разрешён только root. Автоматического удаления старых копий нет — контролируйте свободное место и копируйте архивы за пределы сервера.

Для восстановления администратор останавливает все перечисленные службы, возвращает согласованный набор SQLite/MySQL/файлов/ключей из одной копии по `manifest.json`, восстанавливает конфигурацию и подходящую версию кода, затем выполняет проверки. Установщик намеренно не откатывает базу автоматически: после уже выполненных доставок это могло бы вызвать повторные сообщения.

Ранее на сервере наблюдались перезапуски Telegram poll с `ApiFailure`. Установка WhatsApp сама по себе не доказывает исправление этой отдельной ошибки. Если проверка запуска её обнаружит, бот будет остановлен; изучите журнал и проверьте токен/другой запущенный экземпляр бота.
