# Вложения и ссылки

Вложения хранятся в `ATTACHMENTS_PATH` вне публичного каталога сайта. Максимальный размер файла — 20 000 000 байт. Непредсказуемое имя файла на диске не является публичной ссылкой.

Для ссылок требуется `ATTACHMENTS_PUBLIC_BASE_URL`, например `https://files.example.com/download`. Ссылки имеют вид `<база>/<случайный токен>`. В таблице `attachment_links` хранится только SHA-256 токена; полный URL строится только в памяти перед отправкой и не сохраняется в заданиях или логах. Получатель может переслать ссылку другому человеку.

Первая выдача ссылки фиксирует срок файла: 2 592 000 секунд (30 дней). Ссылки для последующих получателей и повторные попытки сохраняют эту дату. После истечения срока файл нельзя снова опубликовать через тот же storage key; новое объявление должно получить новое вложение. В manifest сохраняются ID вложения и срок. При повторе Worker воспроизводит ту же ссылку через HMAC-SHA256 с приватным 32-байтовым ключом вне SQLite. Удаление просроченных токенов не сбрасывает срок и не удаляет файл: перед удалением blob приложение отдельно проверяет зависимости черновиков, рассылок и заданий.

`public/download.php` поддерживает GET и HEAD. Неизвестный, истёкший токен, отсутствующий либо изменённый файл дают одинаковый пустой ответ 404. Файл отдаётся с `Content-Disposition: attachment`, запретом кэширования и MIME-sniffing. До отправки проверяются размер и SHA-256; PHP-код из вложений никогда не выполняется. Диапазоны байт не используются: GET отдаёт целый ограниченный файл.

Пример конфигурации Nginx: `deploy/attachments-nginx.conf`. Его нужно включить в существующий HTTPS server, указав реальный путь проекта и FPM socket. Не выставлять каталог хранилища как root/alias. Пользователь веб-процесса должен иметь чтение файлов и базы, без права записи вложений. В SQLite WAL-режиме заранее подготовить доступные для чтения служебные WAL/SHM файлы и проверить фактическую работу отдельного пользователя веб-процесса.

На маршруте скачивания отключены access/error logs; также отключить запись полного URL у внешнего reverse proxy/CDN и PHP-FPM. Не использовать токен как метку метрик или ID ошибки. Секреты транспорта веб-процессу не нужны; достаточно `DATABASE_PATH`, `ATTACHMENTS_PATH` и `ATTACHMENTS_PUBLIC_BASE_URL`.

Автоматические проверки используют синтетические файлы и управляемое время. Они не подтверждают наличие HTTPS-домена или доставку настоящему клиенту: это проверяется на тестовом контуре перед серверным запуском.

Поддержка вложений включается переменной `ATTACHMENTS_PATH`; без неё существующая текстовая рассылка сохраняется. Укажите приватный постоянный каталог (в Docker `/data/attachments`). `MAIL_MAX_MESSAGE_BYTES` ограничивает полный MIME письма, по умолчанию 25 000 000 байт. При превышении лимита до отправки вложения заменяются ссылками в одном письме. Для этого нужен настроенный HTTPS-маршрут; без него задание завершится ошибкой и может быть повторено после исправления конфигурации.

Администратор отправляет документы или фотографии в бот, задаёт тему и общий текст, затем `/done`. До 10 файлов по 20 МБ; тема обязательна даже для объявления только с файлами. Перед подтверждением бот показывает все файлы. Содержимое файлов не переводится. Повтор задания продолжает с первой неотправленной части. Неопределённый результат передачи не повторяется автоматически.

Ключ ссылок хранится рядом с базой в `${DATABASE_PATH}.attachment-links.key`, права 0600. Сохраняйте его вместе с резервной копией базы и файлами вложений; SQLite backup сам ключ и файлы не копирует. Потеря ключа при существующих ссылках запрещает выпуск новых ссылок, а уже выданные продолжают разрешаться по хэшу до истечения срока. Веб-процессу ключ не нужен: проверка скачивания читает только хэш в SQLite. Файл ключа исключён из Git и Docker build context.

Загрузка проходит в приватный временный файл внутри хранилища. После успеха или ошибки временный файл удаляется; оставшиеся после аварийного завершения временные файлы старше 24 часов убираются ежедневным заданием. Активные файлы и посторонние имена уборка не затрагивает.
