# Вложения и ссылки

Вложения хранятся в `ATTACHMENTS_PATH` вне публичного каталога сайта. Максимальный размер файла — 20 000 000 байт. Непредсказуемое имя файла на диске не является публичной ссылкой.

Для ссылок требуется `ATTACHMENTS_PUBLIC_BASE_URL`, например `https://service.imenka.world/download`. Ссылки имеют вид `<база>/<непредсказуемый токен>`. В SQLite хранится только SHA-256 токена; задания содержат ID вложения, без полного URL. Токен воспроизводится через HMAC-SHA256 из ID файла, получателя, срока и отдельного случайного ключа длиной 32 байта. В Compose ключ создаётся в отдельном томе приложения: `ATTACHMENTS_LINK_KEY_FILE=/private-links/signing.key`, права 0600; веб-контейнер этот том не получает. Без этой настройки используется `<DATABASE_PATH>.attachment-links.key`. Его нужно сохранять отдельно от SQL-дампа и не включать в Git. Утрата ключа останавливает выпуск ссылок, существующие ссылки продолжают проверяться по хешу. Получатель может переслать ссылку другому человеку.

Первая попытка внешней отправки файла либо ссылки фиксирует срок файла: 2 592 000 секунд (30 дней). Ссылки для последующих получателей и повторные попытки сохраняют эту дату. После истечения срока файл нельзя снова опубликовать через тот же storage key; новое объявление должно получить новое вложение. Worker восстанавливает тот же URL при повторе, не записывая bearer-токен в manifest. Удаление просроченных токенов не сбрасывает срок и не удаляет файл: перед удалением blob приложение отдельно проверяет зависимости черновиков, рассылок и заданий.

`public/download.php` поддерживает GET и HEAD. Неизвестный, истёкший токен, отсутствующий либо изменённый файл дают одинаковый пустой ответ 404. Файл отдаётся с `Content-Disposition: attachment`, запретом кэширования и MIME-sniffing. До отправки проверяются размер и SHA-256; PHP-код из вложений никогда не выполняется. Диапазоны байт не используются: GET отдаёт целый ограниченный файл.

Пример конфигурации Nginx: `deploy/attachments-nginx.conf`; он соответствует FPM из `compose.attachments.yaml` на `127.0.0.1:9005`, путь скрипта внутри контейнера `/app/public/download.php`. Его нужно включить в существующий HTTPS server. Не выставлять каталог хранилища как root/alias. Веб-контейнер получает отдельный том вложений только для чтения, без токенов приложения и HMAC-ключа. Каталог SQLite доступен для создания служебных WAL/SHM, но соединение открывается с `mode=ro` и `PRAGMA query_only=ON`. Полностью read-only том SQLite не подходит: после закрытия последнего writer исчезают WAL/SHM и скачивание получает ошибку открытия базы. Проверить работу от UID 1000.

На маршруте скачивания отключены access/error logs; также отключить запись полного URL у внешнего reverse proxy/CDN и PHP-FPM. Не использовать токен как метку метрик или ID ошибки. Секреты MySQL и транспорта веб-процессу не нужны; достаточно `DATABASE_PATH`, `ATTACHMENTS_PATH` и `ATTACHMENTS_PUBLIC_BASE_URL`.

Закреплённая версия WppConnect принимает документы напрямую до 16 MiB (16 777 216 байт), поэтому большие файлы в пределах общего лимита отправляются ссылкой. Контракт проверен по исходникам версии `cf1098f91c1a1e2028e5d864490f45c72f6b8358`: [HTTP media](https://github.com/wppconnect-team/wppconnect-server-go/blob/cf1098f91c1a1e2028e5d864490f45c72f6b8358/internal/httpapi/media.go), [media limits](https://github.com/wppconnect-team/wppconnect-server-go/blob/cf1098f91c1a1e2028e5d864490f45c72f6b8358/internal/media/media.go).

Автоматические проверки используют синтетические файлы и управляемое время. Они не подтверждают наличие HTTPS-домена или доставку настоящему клиенту: это проверяется на тестовом контуре перед серверным запуском.
