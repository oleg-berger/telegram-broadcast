# Восстановление одобренных пользователей из Excel

Разовый скрипт `bin/import-users.php` работает с текущими зависимостями бота. Для восстановления не требуется менять Application, миграции или почтовую конфигурацию: достаточно положить скрипт в `bin` установленного проекта. Исходный Excel передаётся отдельно; персональные данные не добавлять в Git или публичные артефакты CI.

Скрипт принимает **путь к базе первым аргументом**, путь к XLSX вторым, `--confirm` третьим. Без подтверждения проверяет файл, схему, целостность и конфликты без изменения бизнес-данных. База должна уже существовать и быть мигрирована; ошибочный путь не создаёт пустую базу. Пути лучше использовать абсолютные.

Поддерживается один лист стандартного экспорта бота и только записи `approved` с заполненными данными и датами одобрения. Восстанавливаются прежние Telegram ID, профиль, язык, статус, даты и контакты; интерфейс сразу готов к просмотру анкеты. Telegram-доставка включается: Excel не содержит прежнего признака блокировки бота. История рассылок, очередь и черновики из Excel не восстанавливаются. Старые номера ревизий не используются. Импорт не создаёт задания, уведомления, догоняющую доставку или публикации в канал.

Совпадающие ранее импортированные анкеты пропускаются, в том числе без изменения текущего subscribed. Любое расхождение с существующим профилем, занятый контакт или дубликат в Excel останавливает весь импорт. Существующие заявки не перезаписываются. Все вставки users/contacts идут одной транзакцией; ошибка откатывает их целиком.

## Инструкция администратору — без Docker, Supervisor

1. Положить `import-users.php` в `bin` проекта, `users.xlsx` — в закрытый каталог. Ограничить доступ к Excel (`chmod 600`), дать чтение только оператору/пользователю приложения. Не отправлять содержимое файла или .env в логи и чаты.
2. Через `supervisorctl status` определить именно два процесса бота: poll и worker. Остановить **только их** командами `supervisorctl stop ИМЯ_POLL` и `supervisorctl stop ИМЯ_WORKER`. Не использовать `stop all` на общем сервере. Убедиться, что оба STOPPED. Если они автоматически запускаются другим способом, остановить и его. Скрипт дополнительно проверяет файловые блокировки poll/worker/backup.
3. Перейти в реальный каталог проекта. Дальнейшие PHP-команды выполнять **от того же системного пользователя и тем же PHP 8.4+, что процессы Supervisor**. Требуются существующий vendor/autoload.php и расширения zip, XMLReader, pdo_sqlite, sqlite3 и mbstring.
4. Ввести реальные пути. Путь базы сверить с окружением работающей конфигурации Supervisor: скрипт не определяет его автоматически и не читает .env.

```bash
read -r -p 'Полный DATABASE_PATH из настроек бота: ' BOT_DB
read -r -p 'Полный путь к users.xlsx: ' BOT_XLSX
php bin/import-users.php "$BOT_DB" "$BOT_XLSX"
```

Ожидается `users_import_checked`, `records=4`, `would_insert=4`, `jobs_created=0` для предоставленной выгрузки и пустой базы. Если база действительно ещё не создана, сначала проверить выбранный путь и создать её штатно при остановленных процессах:

```bash
DATABASE_PATH="$BOT_DB" php bin/console migrate
php bin/import-users.php "$BOT_DB" "$BOT_XLSX"
```

Не выполнять migrate по угаданному пути: сервис должен затем использовать именно этот файл. При `users_import_failed` остановиться; в вывод не включаются строки анкет или исходные исключения. Проверить файлы, права, версии зависимостей, формат и конфликты на отдельной копии.

5. После успешной проверки выполнить импорт:

```bash
php bin/import-users.php "$BOT_DB" "$BOT_XLSX" --confirm
php bin/import-users.php "$BOT_DB" "$BOT_XLSX"
```

Первый вывод: `users_imported`, `inserted=4`, `jobs_created=0`. В нём указан `backup` — согласованная SQLite-копия состояния **до** вставки, созданная в `<каталог базы>/backups/before-import/import-<ID>/`. Сохранить её в отдельном защищённом хранилище. Второй вывод: `unchanged=4`, `would_insert=0`; это проверка совпадения всех восстановленных полей и контактов. При повторе подтверждённого импорта совпадающие записи не изменяются.

6. Проверить права базы: она должна оставаться доступной пользователю приложения. Запустить только прежние процессы: `supervisorctl start ИМЯ_POLL` и `supervisorctl start ИМЯ_WORKER`, затем `supervisorctl status`. Не запускать дополнительные poll/worker вручную. Будущие одобренные рассылки включат восстановленных пользователей. Сам импорт никак не уведомляет пользователей; при запуске worker выполняет уже существовавшие задания, если они были в новой базе.

## Откат

Остановить оба процесса. Сохранить текущее состояние и восстановить **согласованную копию из поля backup** штатной командой:

```bash
DATABASE_PATH="$BOT_DB" php bin/console backup
DATABASE_PATH="$BOT_DB" php bin/console restore '/ПОЛНЫЙ/ПУТЬ/ИЗ/ПОЛЯ/backup.sqlite' --confirm
```

Restore заменяет всю базу; изменения после снимка будут потеряны. Затем запустить прежние процессы Supervisor. Не удалять активные SQLite/WAL-файлы вручную. После успешного завершения перенести Excel в закрытый архив либо удалить его рабочую копию по правилам команды; скрипт можно убрать из bin.
