# Последние пять рассылок новому пользователю

После одобрения заявки бот выбирает до пяти последних одобренных рассылок. Собственные рассылки получателя исключаются. Если подходящих рассылок меньше пяти, бот выбирает все доступные.

Порядок определяется моментом одобрения, а не номером черновика. Запись рассылки создаётся при одобрении. Набор фиксируется заданиями очереди в одной транзакции с одобрением пользователя. Неодобренные объявления и старые записи без подтверждённого одобрения не отправляются.

## Переводы и доставка

- Выбор не зависит от общего статуса `ready`, `preparing` или `failed`.
- Для каждой рассылки нужны переведённые текст и тема на язык получателя.
- Ошибка другого языка не отменяет доставку истории новому пользователю. Обычная исходная рассылка сохраняет прежние правила готовности.
- Telegram и email имеют отдельные задания. История входит в отчёт суперадминистратору.
- Задания создаются от старой рассылки к новой. Задержки и повторы API могут изменить фактический порядок получения.
- Успешные доставки и отправленные части сообщения не повторяются. Отписка и блокировка бота сохраняют прежнее действие.

## Старые ошибки перевода

При добавлении новой доставки истории бот может один раз восстановить ранее неуспешное задание перевода текста или темы для выбранного языка. Worker применяет обычные правила: до пяти попыток при временной ошибке; постоянная ошибка завершает задание сразу.

Повторный вызов для того же получателя не сбрасывает попытки. Следующие новые пользователи не дают этому переводу бесконечные дополнительные циклы. Другие языки и старые неуспешные доставки не переоткрываются. Успешные доставки остаются завершёнными.

Если перевод снова завершится ошибкой, сотрудник получит уведомление и отчёт. После устранения причины суперадминистратор может применить `/retry ID`, где ID — номер рассылки, а не черновика. Эта команда повторяет неуспешные задания рассылки, в том числе для старых получателей. Оригинал вместо перевода не отправляется.

## Диагностика

События worker для заданий рассылки содержат `broadcast_id`, `channel`, `language`, а также `job_id` и `kind`. `job_processed` означает обработку задания; оно не доказывает получение сообщения адресатом. Текст, email и токены в события не включаются.

## Обновление

Нужна новая миграция `004_catchup_history.sql`. Она добавляет два поля в `jobs` и не меняет прежние статусы, переводы и счётчики отправленных частей. Старые миграции не изменены.

Обновление не запускает массовую досылку уже одобренным пользователям и не исправляет ранее завершённые задания само по себе. Новая логика действует при последующих одобрениях заявок. Для существующих получателей нужна отдельная проверка и согласованная досылка.

В этой итерации изменены только локальные рабочие копии. Деплой и миграция рабочей БД не выполнялись. При деплое используйте штатную процедуру с резервной копией и остановкой обоих процессов перед явным запуском миграции.
